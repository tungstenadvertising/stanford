# Stanford Medicine MedAdmit Portal 2025

Static HTML content modules for the **Stanford Medicine MedAdmit Portal** admissions experience. Each page is a self-contained layout built with Tailwind CSS, compiled with Vite, and designed to be embedded in the external MedAdmit CMS.

**Live assets (images, JS, compiled CSS):** [https://tungstenadvertising.github.io/stanford/](https://tungstenadvertising.github.io/stanford/)

---

## Overview

This repository is not a traditional single-page web app. It is a **multi-page static site** whose primary deliverable is **copy-pasteable HTML fragments** for the MedAdmit portal. Developers work in `src/`, run a build, then deploy static files to GitHub Pages. The host application loads hero images, scripts, and (optionally) a shared stylesheet from that CDN.

| Concern | Approach |
|--------|----------|
| Styling | Tailwind CSS v4 via `@tailwindcss/vite` |
| Build | Vite 5 (multi-page / MPA) |
| Output | `build/` — flat HTML files + `css/style.css` + copied assets |
| Hosting | GitHub Pages at base path `/stanford/` |
| CMS integration | Marked regions between `Source Code to Copy` comments |

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│  Developer workflow (local)                                      │
│  src/*.html  +  src/css/input.css  +  src/images  +  src/js     │
│       │                                                          │
│       ▼  npm run dev (Vite)                                      │
│  Local preview at /welcome.html (Tailwind processed live)        │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼  npm run build
┌─────────────────────────────────────────────────────────────────┐
│  Build pipeline                                                  │
│  1. vite build        → HTML + bundled css/style.css in build/   │
│  2. cpx               → copy .webp/.svg images + js/ to build/   │
│  3. inject-css.js     → inline CSS into each HTML <head>         │
│                       → rewrite stylesheet href to GitHub CDN    │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼  GitHub Actions (push to feature/css-injection)
┌─────────────────────────────────────────────────────────────────┐
│  GitHub Pages (gh-pages branch)                                  │
│  https://tungstenadvertising.github.io/stanford/                 │
│  Used for: hero images, icons, webp assets, shared JS, CSS URL   │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼  Manual copy into MedAdmit portal
┌─────────────────────────────────────────────────────────────────┐
│  Stanford MedAdmit CMS                                           │
│  Pasted HTML from "Source Code to Copy" regions                  │
│  body#content / .panel-container host shell                      │
└─────────────────────────────────────────────────────────────────┘
```

### Why CSS is injected at build time

MedAdmit pages often cannot rely on a single external stylesheet in the CMS. The post-build step (`inject-css.js`):

1. Reads the compiled `build/css/style.css`
2. Strips the Tailwind license comment block
3. Prepends that CSS into an existing `<style>` tag (or adds one before `</head>`)
4. Rewrites `href="/stanford/css/style.css"` to the absolute GitHub Pages URL

Production HTML is therefore **self-contained for styling** while still referencing CDN-hosted images and scripts.

### Host portal integration

Markup targets the MedAdmit shell:

- `<body id="content">` — matches host selectors (`#content`, `#main`)
- `.panel-container .panel-content` overrides in `input.css` remove default CMS padding when a `.wrapper` is present
- Hero images and many assets use absolute URLs to `tungstenadvertising.github.io/stanford/images/...` so they work after paste into the CMS

## Pages (content modules)

Each HTML file is a separate Vite entry (`rollupOptions.input` in `vite.config.mjs`). Content intended for the CMS sits between HTML comments:

`<!------------- Source Code to Copy: start ------------->`  
`<!------------- Source Code to Copy: end ------------->`

| File | Purpose |
|------|---------|
| `welcome.html` | Portal landing — requirements overview, MedAdmit scope |
| `required-review.html` | Required curriculum & financial aid review |
| `name-pronunciation.html` | Optional name pronunciation upload |
| `required-confirmation.html` | Photo confirmation / upload (uses `required-confirmation.js`) |
| `interview-day-checklist.html` | Pre-interview checklist and resources |
| `interview.html` | Interview invitation messaging |
| `interview-date.html` | Interview date information |
| `about-mmi.html` | Multiple Mini Interview (MMI) information |
| `about-stanford.html` | Campus / program content (Swiper carousel, videos) |
| `congratulations.html` | Admission decision & enrollment actions (GSAP animations) |

There is no client-side router; navigation between screens is handled by the MedAdmit application, not these static files.

### Design tokens (`src/css/input.css`)

Custom theme via `@theme`:

- **Fonts:** Source Sans Pro (primary), Source Serif 4, Galada

Shared layout patterns: `.hero`, `.wrapper` (max-width 1152px), `.hero-divider`, `.square-title`, container queries (`@container`).

## Development workflow

### Prerequisites

- Node.js **24.1.0** (matches CI)
- npm

### Install

```bash
npm install
```

### Local development

```bash
npm run dev
```

- Vite serves from `src/` with `host: true`
- Opens `/welcome.html` by default
- Styles: link to `css/input.css` (Tailwind processed by the Vite plugin)

Edit HTML in `src/` and styles in `src/css/input.css`. Use Tailwind utilities in markup; add component-level rules in `input.css` when host CMS specificity requires `!important` overrides.

### Production build (local)

```bash
npm run build
```

Equivalent to:

1. `vite build`
2. Copy `src/images/**/*.{webp,svg}` → `build/images/`
3. Copy `src/js/**/*` → `build/js/`
4. `node inject-css.js`

Preview the built site:

```bash
npm run preview
```

Serve `build/` with the `/stanford/` base path in mind (or open files and verify asset URLs).

### Image optimization

Convert new JPG/PNG assets in `src/images/` to WebP:

```bash
npm run webp
```

Commit both source and `.webp` variants when adding raster images. HTML should reference `.webp` URLs on GitHub Pages where possible.

### Re-run CSS injection only

After a build, without rebuilding:

```bash
npm run inject
```

## Integrating content into MedAdmit

1. Build locally or wait for CI deploy so CDN assets are current.
2. Open the target `src/<page>.html` in the browser or built `build/<page>.html`.
3. Copy only the markup between **Source Code to Copy** comments (or the full `<body id="content">` inner content per your CMS workflow).
4. Paste into the MedAdmit page editor.
5. Confirm hero images and script tags still point to `https://tungstenadvertising.github.io/stanford/...`.
6. For pages with behavior (`name-pronunciation`, `required-confirmation`), ensure the corresponding `js/*.js` script tag is included.

Pages with inline `<style>` blocks (e.g. `congratulations.html`, `about-stanford.html`) merge with injected Tailwind CSS at build time; the CMS paste should use the **built** HTML from `build/`, not raw `src/` files, for production.

## Notes for contributors

- Prefer **WebP** for photos; keep SVGs for icons and decorative graphics.
- Use absolute GitHub Pages URLs for assets referenced from CMS-embedded HTML.
- Avoid editing `src/css/style.css` — it is build output; change `input.css` instead.
- Large pages (`congratulations.html`) include page-specific `<style>` and CDN scripts; keep third-party URLs stable when updating.
- Test responsive behavior with Tailwind container queries (`@container`, `@2xl:`, etc.) used throughout layouts.
